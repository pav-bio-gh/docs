FDA regulatory records, one list endpoint per record type, each linked to a
Pav company where possible and keyed by FDA identifiers.

| Record type | Endpoint (`/v1/fda/…`) | `from`/`to` date | `status` |
| --- | --- | --- | --- |
| Orange Book products | `orange-book-products` | Approval | `RX`, `OTC`, `DISCN` |
| Orange Book patents | `orange-book-patents` | Patent expiry | `listed` |
| Orange Book exclusivities | `orange-book-exclusivities` | Exclusivity expiry | Exclusivity code |
| Purple Book products | `purple-book-products` | License | Marketing status (`Rx`, …) |
| Orphan designations | `orphan-designations` | Designation | `Designated`, … |
| Drug applications (NDA, ANDA, BLA) | `applications` | First approval | `approved`, … |
| Complete response letters | `complete-response-letters` | Letter | `Approved`, `Unapproved` |
| Accelerated approvals | `accelerated-approvals` | Approval | `ongoing`, `verified`, `withdrawn` |
| Advisory committee meetings | `advisory-committee-meetings` | Meeting | `held`, `scheduled` |
| Warning letters | `warning-letters` | Letter | `issued`, … |
| Recalls | `recalls` | Recall | `active`, … |

`GET /v1/fda/{record_key}` returns one record; URL-encode the key. `GET /v1/fda/applications/{application_key}`
returns an application with every FDA record on it and its submissions
(`records_total`, `submissions_total`).

## Key fields

| Field | Description |
| --- | --- |
| `record_key`, `record_type` | Durable key built from FDA identifiers, and the type. |
| `company`, `fda_organization_name` | Linked Pav company, and the name as FDA spells it. |
| `application_key`, `product_key`, `patent_number` | FDA identifiers (`N:215866`, `N:215866:001`). |
| `title`, `description` | Product or subject, and ingredient, indication or reason. |
| `document_date` | Date FDA issued the record. |
| `event_date`, `event_date_type` | A dated event such as `patent_expiry` or `latest_action`. |
| `source`, `source_version`, `source_url` | FDA publication, edition and page. |
| `details` | Type-specific fields. |

## Parameters

Every FDA list takes these. Orange and Purple Book lists also take `product_key`; Orange
Book patents `patent_number`; orphan designations `designation_id`.

| Name | Values | Example |
| --- | --- | --- |
| `company` | Ticker, company slug or exact name | `lilly` |
| `company_id` | Ids, for values from an earlier response | `218` |
| `application_key` | FDA application | `N:215866` |
| `status` | Statuses, case-insensitive | `listed` |
| `from`, `to` | The date in the table above | `2027-01-01` |
| `sort` | `document_date`, `event_date` | `-event_date` |

Company coverage varies by type: most Orange Book, Purple Book and orphan
records carry a linked Pav company; many warning-letter and recall recipients
do not, so a `company`/`company_id` filter under-counts those two types.

## Example

Orange Book patents held by Eli Lilly, latest expiry first:

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/fda/orange-book-patents \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "company=lilly" \
  --data-urlencode "sort=-event_date" \
  --data-urlencode "limit=2"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/fda/orange-book-patents",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={"company": "lilly", "sort": "-event_date", "limit": 2},
)
resp.raise_for_status()
for r in resp.json()["data"]:
    print(r["patent_number"], r["event_date"], r["title"])
```
