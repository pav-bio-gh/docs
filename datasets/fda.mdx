FDA regulatory records. Each record type is its own resource with a list and
a get endpoint. Records are keyed by FDA identifiers and linked to a Pav
company where possible.

| Record type | Resource (`/v1/…`) | `from`/`to` date | `status` |
| --- | --- | --- | --- |
| Orange Book products | `orange-book-products` | Approval | `RX`, `OTC`, `DISCN` |
| Orange Book patents | `orange-book-patents` | Patent expiry | `listed` |
| Orange Book exclusivities | `orange-book-exclusivities` | Exclusivity expiry | Exclusivity code |
| Purple Book products | `purple-book-products` | License | Marketing status (`Rx`, …) |
| Orphan designations | `orphan-designations` | Designation | `Designated`, … |
| Drug applications (NDA, ANDA, BLA) | `drug-applications` | First approval | `approved`, … |
| Complete response letters | `complete-response-letters` | Letter | `Approved`, `Unapproved` |
| Accelerated approvals | `accelerated-approvals` | Approval | `ongoing`, `verified`, `withdrawn` |
| Advisory committee meetings | `advisory-committee-meetings` | Meeting | `held`, `scheduled` |
| Warning letters | `warning-letters` | Letter | `issued`, … |
| Recalls | `recalls` | Recall | `active`, … |

`GET /v1/<resource>/{record_key}` returns one record of that type, for example
`GET /v1/recalls/{record_key}`. URL-encode the key.

`GET /v1/drug-applications/{application_key}` returns one application with
every FDA record on it and its submissions.

## Fields

Every FDA record has these fields. The [API reference](/api-reference/recalls/list-recalls)
lists every field for each type.

<ResponseField name="record_key" type="string">
  Durable key built from FDA identifiers.
</ResponseField>

<ResponseField name="record_type" type="string">
  Record type, such as `orange_book_patent` or `recall`.
</ResponseField>

<ResponseField name="company" type="object | null">
  The linked Pav company.
</ResponseField>

<ResponseField name="fda_organization_name" type="string | null">
  The applicant, sponsor or recipient name as FDA spells it.
</ResponseField>

<ResponseField name="application_key" type="string | null">
  FDA application, such as `N:215866`.
</ResponseField>

<ResponseField name="product_key" type="string | null">
  Application plus FDA product number, such as `N:215866:001`.
</ResponseField>

<ResponseField name="patent_number" type="string | null">
  Orange Book listed patent number.
</ResponseField>

<ResponseField name="title" type="string">
  Trade name, patent label, letter subject or recalled product.
</ResponseField>

<ResponseField name="description" type="string | null">
  Ingredient, indication, or the subject or reason of a letter or recall.
</ResponseField>

<ResponseField name="document_date" type="string | null">
  When FDA issued the record.
</ResponseField>

<ResponseField name="event_date" type="string | null">
  A dated event, such as a patent expiry.
</ResponseField>

<ResponseField name="event_date_type" type="string | null">
  What `event_date` is, such as `patent_expiry` or `approval`.
</ResponseField>

<ResponseField name="status" type="string | null">
  Status as FDA publishes it. See the table above.
</ResponseField>

<ResponseField name="source" type="string">
  FDA publication the record comes from.
</ResponseField>

<ResponseField name="source_version" type="string | null">
  Edition, such as `2026-08` for the Orange and Purple Books.
</ResponseField>

<ResponseField name="source_url" type="string | null">
  Official FDA page for the record.
</ResponseField>

<ResponseField name="details" type="object">
  Fields specific to the record type.
</ResponseField>

## Filters

Every FDA list takes these filters. See [Fetching data](/fetching-data) for
how filters, dates, sorting and paging work.

<ParamField query="company" type="string">
  Ticker, company slug or exact company name. Example: `lilly`.
</ParamField>

<ParamField query="application_key" type="string">
  FDA application. Example: `N:215866`.
</ParamField>

<ParamField query="status" type="string">
  One or more statuses from the table above. Case is ignored.
</ParamField>

<ParamField query="company_id" type="string">
  One or more Pav company ids.
</ParamField>

<ParamField query="from" type="date">
  Records on or after this date. The date depends on the type; see the table
  above.
</ParamField>

<ParamField query="to" type="date">
  Records on or before this date.
</ParamField>

<ParamField query="sort" type="string">
  `document_date` or `event_date`. Prefix `-` for descending.
</ParamField>

Some types take one more filter:

<ParamField query="product_key" type="string">
  Orange Book products, patents and exclusivities, and Purple Book products.
  Example: `N:215866:001`.
</ParamField>

<ParamField query="patent_number" type="string">
  Orange Book patents.
</ParamField>

<ParamField query="designation_id" type="string">
  Orphan designations.
</ParamField>

Most Orange Book, Purple Book and orphan records are linked to a Pav company.
Many warning letter and recall recipients are not, so a company filter misses
some of those.

## Example

Orange Book patents held by Eli Lilly, latest expiry first:

<CodeGroup>

```bash cURL icon="braces"
curl -G https://api.pav.bio/v1/orange-book-patents \
  -H "Authorization: Bearer $PAV_API_KEY" \
  -d company=lilly \
  -d sort=-event_date \
  -d limit=2
```

```python Python SDK icon="python"
from pav_bio import Pav

client = Pav()  # reads PAV_API_KEY

patents = client.orange_book_patents.list(
    company=["lilly"],
    sort="-event_date",
    limit=2,
)
for patent in patents.items:
    print(patent.patent_number, patent.event_date, patent.title)
```

```bash CLI icon="terminal"
pav orange-book-patents list \
  --company lilly \
  --sort=-event_date \
  --limit 2
```
