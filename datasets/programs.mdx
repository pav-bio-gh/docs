## Overview

A program is one drug in one indication at one company. Programs come from the
pipelines companies publish, their filings and announcements, FDA-approved uses
of drugs the company still develops, and, for companies that publish no
pipeline, their registered clinical trials (see `basis`). Each
program carries a normalized phase, a modality, the molecular target and
mechanism when known, a lifecycle status, the clinical trials linked to it,
and the page it was read from.

Questions this dataset answers:

- Which companies have an oral GLP-1 agonist in development for obesity?
- Which KRAS G12C inhibitors are in Phase 3, and in which indications?
- What else is being developed against this target?
- What is Eli Lilly's full Phase 3 pipeline?

## Status

Every program has a `status`. List and search endpoints return only `active`
programs unless you pass `status`.

| `status` | Meaning |
| --- | --- |
| `active` | In development or on the market. A drug with a recorded approval stays `active` after the company moves it off its pipeline page. |
| `inactive` | Known only from clinical trials, and all of its trials have closed. It returns to `active` if a trial opens. |
| `discontinued` | Dropped from the company's pipeline. |

Repeat `status` to combine values: `status=active&status=discontinued`. An
unknown value returns `422`. A `discontinued` program carries
`discontinued_at`, for example Novartis's lifonebart in ALS (program `10521`):
`"discontinued_at": "2026-08-25T00:00:00Z"`.

## How phase is decided

Phase is the development stage the developer reports for this drug in this
indication (its pipeline, filings and announcements), or a US or EU
regulatory approval. Only when the developer reports no phase is it taken from
the most advanced registered clinical trial of the same drug in the same
indication. A trial never raises a phase the developer reports, so a program
can list a trial at a later stage than its phase. A program's trials are the
registered trials of the same drug in the same disease; trials of the drug in
other diseases belong to those programs.

Failing all of these, phase is the phase a public source (a press release,
filing or registry record) states for the program. When the developer's
pipeline page has not been readable for a long time, a public source dated
after its last reading takes the place of the page's phase.

`phase` keeps the developer's own label. `phase_norm` is the normalized phase,
and is `Approved` when a US or EU approval covers the indication, even if the
developer still lists an earlier stage.

## Key fields

| Field | Description |
| --- | --- |
| `id` | Pav program id. Stable: a phase change updates the program, and a discontinued program keeps its id. |
| `status` | `active`, `inactive` or `discontinued`. See [Status](#status). |
| `discontinued_at` | For a `discontinued` program, when it stopped: the date the company or a reviewer stated the stop, or the first check that found it gone from the pipeline. `null` while `active` or `inactive`. |
| `basis` | How Pav knows of the program: `company_pipeline` (the company lists or announces it), `regulatory_approval` (an FDA-approved use of a drug the company still develops that its pipeline does not list; `phase_norm` is `Approved` and `source_url` is the FDA label), or `clinical_trial_registry` (known only from registered clinical trials). |
| `company_id`, `company`, `short_name` | Owning company: Pav id, display name, slug. |
| `drug` | Drug or asset name as the company publishes it. |
| `drug_id`, `aliases` | The Pav drug shared by every company's programs of the same drug product, and the drug's other names (INN, research codes, brands). `null` for an undisclosed asset. See [Drugs](/datasets/drugs). |
| `indication` | Indication as the company publishes it. |
| `phase` / `phase_norm` | Phase as published, and the normalized phase (`Preclinical`, `Phase 1`, `Phase 1/2`, `Phase 2`, `Phase 2/3`, `Phase 3`, `Filed`, `Registration`, `Approved`). See [How phase is decided](#how-phase-is-decided). |
| `modality` / `modality_norm` | Modality as published, and the normalized modality (`small_molecule`, `antibody`, `adc`, `cell_therapy`, `rna`, ...). Assigned per drug, so every program of one `drug_id` has the same `modality_norm`. |
| `modality_subclass` | Nucleic-acid class for `rna` and `oligonucleotide` drugs: `sirna`, `mrna`, `sarna`, `rna_editing`, `aso` or `aptamer`. |
| `modality_formats[]` | Format facets: `bispecific` (bi-, tri- and multispecifics), `antibody_drug_conjugate`, `peptide_drug_conjugate`, `antibody_oligonucleotide_conjugate`, `antibody_peptide_conjugate`. |
| `target`, `mechanism_of_action` | Molecular target and mechanism, when known. |
| `partners` | Partners the company lists for the program. When it lists none, the other companies that develop or market the same drug, outside the company's own corporate family. |
| `clinical_trials[]` | Linked ClinicalTrials.gov studies (`nct_id`, phase, status, sponsor, conditions). |
| `indication_terms[]` | MONDO disease terms for the indication. A program that covers several diseases has one term per disease. |
| `target_terms[]` | NCIT or HGNC terms for the target, each with `gene_symbol` (the official HGNC symbol, `null` for non-gene targets). Group and match targets by `gene_symbol`. |
| `source_url`, `source_checked_at` | The page the program was read from (the FDA label for a `regulatory_approval` program), and when Pav last read it. |

Fields with no value are omitted from the JSON. List fields such as
`partners` and `modality_formats` can be empty arrays.

Full schema: [List and search pipeline programs](/api-reference/programs/list-and-search-pipeline-programs).

## Endpoints

| Endpoint | Use |
| --- | --- |
| `GET /v1/programs` | Search (`q`) or filter programs. |
| `GET /v1/programs/{program_id}` | One program with its trials and ontology terms. |
| `GET /v1/programs/{program_id}/similar-programs` | Programs of other drugs most similar to a given program. |
| `GET /v1/programs/autocomplete` | Search-as-you-type suggestions for a search box. |
| `GET /v1/companies/{company_id}/programs` | One company's programs. |
| `GET /v1/drugs/{drug_id}` | One drug's programs across every company. See [Drugs](/datasets/drugs). |

## Filters

All filters are optional and combine with AND. Repeating a filter matches any
of its values.

| Parameter | Matches | Example |
| --- | --- | --- |
| `q` | Relevance-ranked search that matches meaning as well as exact words. See [Search with `q`](#search-with-q). | `oral GLP-1 obesity` |
| `status` | Lifecycle states. Default `active`. | `discontinued` |
| `phase` | Normalized phase label, exactly as in `phase_norm`. | `Phase 3` |
| `modality` | Modality token or display label, a nucleic-acid subclass (`siRNA`, `mRNA`, `saRNA`, `ASO`, `aptamer`, `RNA editing`) or a format (`bispecific`, `antibody_drug_conjugate`, ...). Unknown values return `422` listing the accepted forms. | `adc`, `siRNA`, `bispecific` |
| `target` | The target as written, a target term label or id (NCIT or HGNC), a gene symbol, or a common alias. `TL1A`, `TNFSF15` and `NCIT:C18289` return the same programs, including multi-target programs. | `TL1A` |
| `indication` | The indication as written, its MONDO term label or id, or an exact synonym. Includes programs for narrower diseases: `lung cancer` includes non-small cell lung carcinoma. | `NSCLC`, `MONDO:0005233` |
| `drug` | Drug name. Case, punctuation and trademark signs are ignored, and a name also matches inside a longer one: `sotorasib` matches `LUMAKRAS® (sotorasib)`, and a drug matches combinations that include it. | `tirzepatide` |
| `drug_id` | Every company's programs of one drug. | `4781` |
| `company` | Company name, slug, or another name the company is known by. | `MSD`, `Merck & Co.` |
| `company_id` | Pav company id. Includes the companies it owns unless `include_subsidiaries=false`. | `218` |
| `short_name` | Company slug. | `eli_lilly` |
| `view` | `full` (default) or `slim`: light rows with `trial_count` instead of nested trials and terms. | `slim` |
| `sort`, `direction` | Listing order: `company`, `drug`, `indication`, `target`, `phase`, `modality`, `source_checked_at`. | `sort=phase&direction=desc` |
| `include_total` | Exact match count in `pagination.total`, with or without `q`. | `true` |
| `limit`, `offset` | Page size (1–5000, default 50) and offset. | `limit=100` |

<Warning>
`phase` takes the label shown in `phase_norm` (`Phase 3`), not a token such as
`phase_3`. A `phase` that matches nothing returns an empty `data` array, not an
error. `target` and `modality` return only programs where the field is known.
</Warning>

## Search with `q`

`q` finds programs by meaning, not only by exact words, ranked best match
first. It reads the drug's type and the disease hierarchy:
`siRNA for hypercholesterolemia` ranks siRNA programs first, and
`pancreatic cancer` also finds pancreatic ductal adenocarcinoma programs.
Spellings of a target such as `Claudin 18.2`, `CLDN18.2` and `Claudin18.2`
return the same programs.

Relevance search returns `pagination.total` as `null`. When you pass `sort`
or `include_total=true`, or page past 1,000 rows, `q` instead returns every
program matching all of its words, in listing order, with an exact total. A
`q` with no letters or digits returns no rows. `%` and `_` are matched
literally.

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/programs \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "q=KRAS G12C inhibitor" \
  --data-urlencode "phase=Phase 3" \
  --data-urlencode "limit=3"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/programs",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={"q": "KRAS G12C inhibitor", "phase": "Phase 3", "limit": 3},
)
resp.raise_for_status()
for p in resp.json()["data"]:
    print(p["company"], "|", p["drug"], "|", p.get("indication", ""), "|", p.get("target"))
```

```javascript JavaScript
const params = new URLSearchParams({ q: "KRAS G12C inhibitor", phase: "Phase 3", limit: "3" });
const resp = await fetch(`https://api.pav.bio/v1/programs?${params}`, {
  headers: { Authorization: `Bearer ${process.env.PAV_API_KEY}` },
});
const { data } = await resp.json();
for (const p of data) console.log(p.company, "|", p.drug, "|", p.indication, "|", p.target);
```

## Filter and count

Without `q`, the endpoint lists programs matching the filters. Pass
`include_total=true` for the exact count. `indication=obesity` matches every
phrasing mapped to the obesity term, such as "Overweight or Obese Adults".

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/programs \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "indication=obesity" \
  --data-urlencode "phase=Phase 2" \
  --data-urlencode "phase=Phase 3" \
  --data-urlencode "include_total=true" \
  --data-urlencode "limit=3"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/programs",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={
        "indication": "obesity",
        "phase": ["Phase 2", "Phase 3"],
        "include_total": "true",
        "limit": 3,
    },
)
resp.raise_for_status()
body = resp.json()
print("total:", body["pagination"]["total"])
for p in body["data"]:
    print(p["company"], "|", p["drug"], "|", p["indication"], "|", p["phase_norm"])
```

```javascript JavaScript
const params = new URLSearchParams([
  ["indication", "obesity"],
  ["phase", "Phase 2"],
  ["phase", "Phase 3"],

  headers: { Authorization: `Bearer ${process.env.PAV_API_KEY}` },
});
const body = await resp.json();
console.log("total:", body.pagination.total);
for (const p of body.data) console.log(p.company, "|", p.drug, "|", p.indication, "|", p.phase_norm);
```

## Find similar programs

Given a program id, return programs of other drugs ranked by similarity: first
those sharing its target, then its indication, then its modality and a nearby
phase. The same drug is never returned, and each drug appears once. `limit`
is 1–50 (default 5); `exclude_same_company=true` leaves out the company's own
programs.

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/programs/1833/similar-programs \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "limit=3" \
  --data-urlencode "exclude_same_company=true"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/programs/1833/similar-programs",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={"limit": 3, "exclude_same_company": "true"},
)
resp.raise_for_status()
for p in resp.json()["data"]:
    print(p["company"], "|", p["drug"], "|", p.get("indication", ""), "|", p.get("target"))
```

```javascript JavaScript
const params = new URLSearchParams({ limit: "3", exclude_same_company: "true" });
const resp = await fetch(`https://api.pav.bio/v1/programs/1833/similar-programs?${params}`, {
  headers: { Authorization: `Bearer ${process.env.PAV_API_KEY}` },
});
const { data } = await resp.json();
for (const p of data) console.log(p.company, "|", p.drug, "|", p.indication, "|", p.target);
```

## Get one program

`GET /v1/programs/{program_id}` returns the full record, including linked
trials and ontology terms. An id that was merged into another program returns
the surviving program.

```bash
curl https://api.pav.bio/v1/programs/1833 \
  -H "Authorization: Bearer $PAV_API_KEY"
```
