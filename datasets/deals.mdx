## Overview

A deal is one biopharma transaction: an acquisition, merger, asset purchase,
licensing agreement, collaboration, option, joint venture or distribution
agreement. Each deal keeps one stable `deal_id` as new filings and releases
report on it, and carries its parties and their roles, its headline
economics, its lifecycle from proposal to completion or termination, the drugs
it covers, and the source documents behind every term.

Questions this dataset answers:

- What are the largest biopharma acquisitions by headline value?
- Which deals has Eli Lilly done this year, and on what terms?
- Which deals cover a TL1A antibody, or an ADC?
- Where does a stated upfront or milestone figure come from?

## Coverage

| Deals | Sources | Tagged with a drug | Updated |
| --- | --- | --- | --- |
| 3,300+ (September 2026) | SEC filings and company press releases | 43% | As new filings and releases are published |

About half of deals state a value. `min_value_usd` and the value sorts consider
only deals with a stated value. A deal carries drug, target, modality and
therapeutic-area tags only when its documents name a specific drug that Pav
tracks; platform and portfolio deals carry none.

## Key fields

| Field | Description |
| --- | --- |
| `deal_id` | Stable Pav deal id (UUID). |
| `deal_name`, `summary` | Headline and a one-paragraph summary. |
| `deal_type` | `acquisition`, `merger`, `asset_purchase`, `licensing`, `collaboration`, `option`, `joint_venture`, `distribution`, `other`. |
| `latest_event_type` | Current lifecycle state: `proposed`, `announced`, `amended`, `completed` or `terminated`. It never moves backwards: a completed deal stays completed, and a takeover bid that lost to another buyer is `terminated`. |
| `latest_event_name`, `latest_event_at` | The event that set the current state, and when it took effect. `latest_event_at` is `null` when a closing is reported with no date. |
| `announced_at`, `completed_at`, `latest_update_at` | Lifecycle dates (UTC). |
| `activity_date` | The later of `latest_event_at` and `latest_update_at`. Default sort. |
| `companies[]` | Parties linked to Pav companies, with their `roles`: `acquirer`, `target`, `seller`, `licensor`, `licensee`, `collaborator`, `investor`, `issuer` or `other`. |
| `total_value` | Headline value as the announcement states it: `raw_text`, `amount`, `currency`, `not_disclosed`, and the `evidence` sentence it came from. Never a per-share price. |
| `total_potential_value` | `total_value` when stated; otherwise upfront plus milestones in one currency. `raw_text` shows the parts that were added. |
| `upfront`, `development_milestones`, `regulatory_milestones`, `commercial_milestones` | Stated economics, in the same shape. |
| `assets[]` | Drugs the deal covers: `drug_id`, `name`, `modality`, and `program_ids` (the deal parties' programs of that drug). |
| `targets[]`, `modalities[]`, `therapeutic_areas[]` | Tags that come from the drugs the deal covers: target terms with `gene_symbol`, modalities, and therapeutic-area slugs. |
| `source_document_count`, `event_count` | How many documents and lifecycle events back the deal. |

`GET /v1/deals/{deal_id}` adds `terms` (headline value, total potential value,
upfront, equity, milestones, royalties, territories, rights), `events[]` with
the source URL of each lifecycle step, and `source_documents[]`.

## Endpoints

| Endpoint | Use |
| --- | --- |
| `GET /v1/deals` | Search and filter deals. |
| `GET /v1/deals/{deal_id}` | One deal with full terms, events and sources. |

## Filters

All filters are optional and combine with AND. With no filters you get the most
recent deal activity.

| Parameter | Matches | Example |
| --- | --- | --- |
| `q` | Every term must appear in the deal name, event headline, summary or rights (word forms such as plurals also match), or `q` is a substring of a party's name. No synonym expansion. | `ADC` |
| `company_id` | Deals with this company as a party. Repeatable. | `218` |
| `deal_type` | Deal type. Repeatable. | `licensing` |
| `event_type` | Current lifecycle state. Repeatable. | `completed` |
| `drug_id` | Deals covering this drug, whatever name each document uses. Repeatable. | `11873` |
| `target` | Deals covering a drug with this target. Same matching as the program `target` filter: `TL1A`, `TNFSF15` and `NCIT:C18289` are the same. | `TL1A` |
| `modality` | Deals covering a drug of this modality. Same values as the program `modality` filter. | `adc`, `siRNA`, `bispecific` |
| `therapeutic_area` | Deals covering a drug developed for a disease in this area. Slugs: `cardiovascular`, `dermatology`, `endocrine_metabolic`, `gastroenterology`, `hematology`, `hepatology`, `immunology`, `infectious_disease`, `musculoskeletal`, `nephrology`, `neurology`, `oncology`, `ophthalmology`, `otolaryngology`, `psychiatry`, `reproductive_womens_health`, `respiratory`, `urology_mens_health`. Others return `422`. | `oncology` |
| `announced_from`, `announced_to` | Announcement date range, inclusive. | `2026-01-01` |
| `min_value_usd` | Minimum `total_potential_value` in USD. | `1000000000` |
| `sort` | `latest_activity` (default), `announced_at`, `completed_at`, `headline_value`, `total_potential_value`; newest or largest first. | `headline_value` |
| `include_total` | Exact match count. | `true` |
| `limit`, `offset` | Page size (1–100, default 25) and offset. | `limit=50` |

`q` searches deal text; `target`, `modality`, `drug_id` and
`therapeutic_area` use the drug tags. A deal whose drugs have no known target
or modality never matches those filters.

## Largest deals

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/deals \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "min_value_usd=1000000000" \
  --data-urlencode "sort=headline_value" \
  --data-urlencode "limit=3"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/deals",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={"min_value_usd": 1_000_000_000, "sort": "headline_value", "limit": 3},
)
resp.raise_for_status()
for d in resp.json()["data"]:
    print(d["deal_name"], "|", d["total_value"]["raw_text"], "|", d["latest_event_type"])
```

```javascript JavaScript
const params = new URLSearchParams({ min_value_usd: "1000000000", sort: "headline_value", limit: "3" });
const resp = await fetch(`https://api.pav.bio/v1/deals?${params}`, {
  headers: { Authorization: `Bearer ${process.env.PAV_API_KEY}` },
});
const { data } = await resp.json();
for (const d of data) console.log(d.deal_name, "|", d.total_value.raw_text, "|", d.latest_event_type);
```

## Deals by target

`target` finds deals whose drugs act on a target, under any of its names.

<CodeGroup>

```bash cURL
curl -G https://api.pav.bio/v1/deals \
  -H "Authorization: Bearer $PAV_API_KEY" \
  --data-urlencode "target=TL1A" \
  --data-urlencode "include_total=true" \
  --data-urlencode "limit=5"
```

```python Python
import os
import requests

resp = requests.get(
    "https://api.pav.bio/v1/deals",
    headers={"Authorization": f"Bearer {os.environ['PAV_API_KEY']}"},
    params={"target": "TL1A", "include_total": "true", "limit": 5},
)
resp.raise_for_status()
body = resp.json()
print("total:", body["pagination"]["total"])
for d in body["data"]:
    value = (d.get("total_potential_value") or {}).get("raw_text", "undisclosed")
    print(d["announced_at"][:10], "|", d["deal_name"], "|", [a["name"] for a in d["assets"]], "|", value)
```

```javascript JavaScript
const params = new URLSearchParams({ target: "TL1A", include_total: "true", limit: "5" });
const resp = await fetch(`https://api.pav.bio/v1/deals?${params}`, {
  headers: { Authorization: `Bearer ${process.env.PAV_API_KEY}` },
});
const body = await resp.json();
console.log("total:", body.pagination.total);
for (const d of body.data) {
  const value = d.total_potential_value?.raw_text ?? "undisclosed";
  console.log(d.announced_at.slice(0, 10), "|", d.deal_name, "|", d.assets.map((a) => a.name), "|", value);
}
```
